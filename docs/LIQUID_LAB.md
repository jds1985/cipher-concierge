# Liquid browser lab

Isolated from `/stay`. The page returns 404 unless `LIQUID_BROWSER_EXPERIMENT=1`. Nothing here changes the live guest route, the Cipher WASM model, or production environment variables. Weights are not in git.

## What was verified

`LiquidAI/LFM2.5-350M-ONNX` exists. Pinned revision `d11593fd9eb408e322667926656598896c2d5ff9` (Hugging Face API, 2026-11-06).

- License on that repo: **LFM Open License v1.0** (`license_name: lfm1.0`). Research use is granted. Commercial use by an entity at or above $10M annual revenue is not granted by that license. The license file is downloaded next to the weights.
- Architecture: `Lfm2ForCausalLM`. `config.json` includes `transformers.js_config`.
- Official Liquid browser snippet uses `onnxruntime-web` and says WebGPU is required. It does not document a WASM CPU fallback.
- Official Transformers.js path: `@huggingface/transformers` 4.3.2. Release 4.3.0's example loads `onnx-community/LFM2.5-350M-ONNX` with `dtype: "q4f16"` and `device: "webgpu"`. LFM2 itself was added in Transformers.js 3.7.0, where the default device is WASM and `dtype: "q4"` is the example. This lab uses 4.3.2, tries WebGPU q4f16, then WASM q4f16, then WASM q4.
- Measured files from the Liquid repo (same sizes the Hugging Face tree API lists for `onnx-community/LFM2.5-350M-ONNX`):

| File | Bytes |
|---|---|
| `onnx/model_q4f16.onnx` | 182,827 |
| `onnx/model_q4f16.onnx_data` | 254,965,760 |
| `onnx/model_q4.onnx` | 183,442 |
| `onnx/model_q4.onnx_data` | 293,629,952 |

q4f16 is the ~250 MB weight (243.3 MiB). Liquid's card table calls Q4 ~276 MB; the Q4 data file is 280.0 MiB. `model_q4f16.onnx` and `config.json` are byte-identical to `onnx-community/LFM2.5-350M-ONNX` (SHA-256 `3012c28a119828561c90196331435d91c43c1a6ab4898ac79715585fff1dff85` and `544d8d604bacf4cb89383c49c9a54621afa26a6741f3f55fd8b840ca1d640419`). The community repo is the one whose model card sets `library_name: transformers.js` and prints a `pipeline()` example. The weights exercised here are the Liquid repo files.

Runtime pinned for the test: `onnxruntime-web` `1.31.0-dev.20260914-8d85527a0`, loaded from this origin. `env.allowRemoteModels` is false.

## Run

```bash
npm ci
npm run fetch-liquid-lab
LIQUID_BROWSER_EXPERIMENT=1 QR_SECRET="$(openssl rand -base64 48)" npm run dev
```

Open `/lab/liquid/<hotel>/<room>?t=<token>` from a signed room link. `/stay/...` is the live page and does not load this model.

`npm run test:liquid-lab` builds, checks the lab stays 404 when the flag is off, then runs a real Chrome session. A desktop session is not a physical phone test.

## Behavior

Hotel facts, multi-fact questions, unknown amenities, and emergencies come from the existing facts engine. The model sees only an unmatched general clause, plus retrieved fact lines. A draft that invents an amenity, password, or number is discarded without a front-desk referral. Staff notes leave the phone only after the checkbox is turned on, and that request is not the chat transcript.

## Measured on this VM (2026-11-06)

Desktop Chrome 156 headless only. No guest sentence was generated by the model.

- WebGPU q4f16: session created in 23.3s. Generation failed in 237 ms because the shader compiler requires f16 and `shader-f16` is false. Init only.
- WebGPU q4: warmup compiled for 7 min 53 sec at about 329% GPU-process CPU and 872 MB, with no token. Stopped once. Not restarted.
- WASM q4, the Transformers.js CPU dtype, failed in 23.2s: ONNX Runtime has no `GatherBlockQuantized` kernel for `/model/embed_tokens/Gather_Quant`. The weights loaded. The session did not.
- Fact answers (Wi-Fi, quiet hours, checkout plus Wi-Fi, spa, 911) stayed on the facts engine. Question text did not appear in any request. No foreign host was contacted.
- Live `/` and `/stay` CSP stayed the production policy. `/lab` is 404 unless `LIQUID_BROWSER_EXPERIMENT=1`.

## Phone gate

Do not hand Jim a phone task from this lab. The next physical check, on a guest Android and an iPhone, is: QR scan, model copy finishes, a fact answer does not spin the model, one open answer generates, airplane mode still answers from cache, and a proxy or the phone's network log shows no guest sentence leaving the device. Budget roughly 250 MB of weights plus the WASM runtime, and expect about 1 GB of RAM while generating. iOS Safari WebGPU and background tab eviction are untested here.
